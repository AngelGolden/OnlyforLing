# Photos 相册功能完善指令

## 一、任务目标

完善当前模拟器中已经存在的 Photos 相册 App。

本次不是重新开发相册，而是在现有功能基础上实现：

1. 用户自行添加照片。
2. 相册以真实手机照片网格形式展示。
3. 点击具体照片后打开照片详情。
4. 在照片下方显示拍摄日期、时间、地点（如果有）和自定义说明。
5. 支持不同照片拥有不同的说明。
6. 照片和说明能够持久化保存。

## 二、执行限制

1. 先检查当前 Photos App 的组件结构、照片数据结构和已有图片资源加载方式。
2. 沿用现有架构和数据格式，优先扩展，不要重写相册。
3. 不修改 WhatsApp、Instagram、Notes、论坛等其他 App。
4. 不重构全局状态管理或消息系统。
5. 不新增 AI 自动生成照片说明的功能。
6. 不自行创建或下载任何照片，照片由用户自行添加。
7. 如果现有结构已经支持照片元数据，只需补充缺少的展示和编辑功能。
8. 如现有数据结构与本文建议不同，以兼容现有系统为优先，并向用户说明实际采用的字段映射。

## 三、照片数据格式

每张照片需要具有独立 ID 和独立元数据。

建议结构如下：

```json
{
  "id": "photo_20251018_001",
  "image": "用户添加的图片资源",
  "capturedAt": "2025-10-18T18:42:00",
  "location": "Hong Kong",
  "caption": "第一次正式跟大家一起排练。那天有点紧张，幸好大家都挺好相处的。",
  "favorite": false,
  "album": "recent"
}
```

字段说明：

- `id`：照片唯一标识。
- `image`：图片文件或资源路径，必须由实际添加的图片提供。
- `capturedAt`：拍摄时间。
- `location`：地点，可为空。
- `caption`：照片说明，可为空。
- `favorite`：收藏状态。
- `album`：相簿归属。

注意：不得把示例图片路径当作真实图片路径。用户添加图片后，再关联实际资源。

## 四、照片网格界面

保留现有相册主界面。

要求：

- 照片以三列网格展示。
- 默认按照拍摄时间倒序排列。
- 缩略图尽量保持统一尺寸。
- 点击照片进入详情页。
- 返回后保留原来的滚动位置。
- 没有说明的照片仍然可以正常打开。
- 不要在缩略图上叠加剧情说明。

## 五、照片详情界面

点击某张照片后：

1. 显示对应的大图。
2. 在照片下方显示日期和具体时间。
3. 如果有地点，则显示地点。
4. 如果有 caption，则显示 caption。
5. 如果没有 caption，则不显示空白说明区域。
6. 不同照片必须读取各自对应的元数据，不能共用同一条说明。
7. 返回按钮返回相册网格，不重置滚动位置。

展示示例：

2025年10月18日

星期六 · 18:42

Hong Kong

第一次正式跟大家一起排练。那天有点紧张，幸好大家都挺好相处的。后来才发现，原来自己真的会开始期待每一次排练。

## 六、照片说明编辑

用户可以在照片详情页编辑 caption：

- 点击说明区域进入编辑。
- 修改后自动保存。
- 再次打开照片时显示修改后的内容。
- 刷新页面、关闭 App 后内容仍然保留。
- 不允许初始化时覆盖用户编辑过的说明。

## 七、持久化

照片元数据和图片资源需要正确关联。

如果现有系统已经有持久化机制，继续沿用。

不得仅把说明存储在组件临时 state 中。

## 八、验收要求

请只验证本次涉及的功能：

1. 添加一张照片后，网格能够正常显示。
2. 点击该照片，能显示正确的大图。
3. 显示的日期、时间、地点和说明均属于该照片。
4. 修改说明后退出再进入，修改内容仍然存在。
5. 没有说明的照片不会出现空白说明框。
6. 返回网格后滚动位置不丢失。
7. 原有照片和原有相册功能没有损坏。

完成后汇报：
- 实际修改的文件。
- 采用的照片数据字段。
- 用户应该如何添加图片及关联 caption。
- 上述验收项目的测试结果。

不要进行与本任务无关的重构。
